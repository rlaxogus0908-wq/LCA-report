# Complete the BC1 factory-gate model

1. Confirm the physical product and each material specification. The BOM gives finished mass only. For each material, record purchase mass as `finished_mass_kg / yield_fraction` with evidence for the yield and separate scrap treatment. Do not use finished mass as procurement without documenting a 100% yield assumption.
2. Select a supplier process for every purchased material and conversion service. Record exact dataset ID, release/version, geography, reference amount/unit, source URL, retrieval date, and file hash where available in `candidate_mapping.csv`. Review the license before including raw records in a public repository.
3. Quantify component fabrication, assembly electricity, packaging conversion, and inbound transport within the factory-gate boundary. Avoid adding a separate conversion process if the selected supplier dataset already includes it. Exclude customer delivery, use, and end of life.
4. Import all connected unit processes into a JSON model matching `examples/site_matrix_example.json`: one unique product reference flow per process; nonnegative technosphere input amounts with explicit provider IDs; signed elementary amounts with a flow ID, compartment, and unit. The `examples/kettle_model_template.json` file lists the required material inputs but deliberately has no purchase amounts or providers.
5. Use one compatible characterization method. This repository's CSV includes four IPCC AR6 GWP100 gas factors. Add every other climate-relevant elementary flow from the chosen inventories with an authoritative factor and exact identity. The solver rejects a flow without a factor. Check fossil and non-fossil methane, biogenic CO2, uptake, land-use CO2, and any other method-specific distinctions.
6. Run `python src/lcia.py calculate --model PATH_TO_COMPLETE_MODEL.json --factors data/ipcc_ar6_gwp100.csv --out results/kettle_complete.json`. The solver performs `A s = f`, `g = B s`, `h = C g`, checks units and provider links, and reports contributions by process. A successful mathematical solve does not itself prove complete system boundaries; compare the provider graph with the process map and data manifest.
7. Update README and run manifest from actual results. Preserve the first complete independent run and its Git commit before any class comparison; place a changed-choice scenario in a separate file and commit.
